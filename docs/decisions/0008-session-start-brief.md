# ADR 0008: セッション開始時に日報から引き継ぎ、準備作業と繰り返しを示す

- 状態: 採用
- 日付: 2026-11-13

## 背景

日報を「書く」仕組みはできたが、「読む」のは人の手間のままだった。新しいセッションのたびに前回の続きを説明し、PCでしかできない作業を Web版で頼んで止まる、同じ準備作業（プラグインの登録、エディタの起動など）を毎回手でやる、といった無駄が日報メモからも読み取れる。

## 選択肢

| 案 | 内容 | 欠点 |
| --- | --- | --- |
| A 人が日報を読んで伝える | 今のまま | 手間が残る。書いた日報が使われない |
| **B SessionStart フックで渡す** | 最新のメモ、作業キュー、リポジトリの状態、繰り返しの判別を短くまとめて Claude の文脈に入れる | 文脈が少し増える。判別は推定 |
| C 分析レポートを毎回読ませる | 分析ツールの全出力を渡す | 長すぎて依頼の妨げになる |

## 決定

案Bを採用する。

- 出すのは4項目（次にやること、判断待ち、始める前の準備、効率化の候補）で、各2〜8件に絞る。何もなければ何も出さない
- ネットワークを使わない（`git fetch` しない）。失敗しても作業を止めない。`DAILY_LOG_SKIP=1` で止められる
- 環境（Web版 / PC）を判定し、Web版では PC の作業に印を付ける
- リポジトリごとの決まった準備は `docs/log/config.json` の `prep` に書く（コードを変えずに足せる）
- 繰り返しの判別は、文の似ている度合い（ひらがなを除いた内容の言葉でも比べる）と、準備作業の言葉の出現日数の2つで行う。英字だけの文と日本語の文は、ほぼ同じときだけ同じ作業とみなす（実装のコミットと登録の作業を混同しないため）

## 影響

- 導入・更新時に `.claude/settings.json` へ SessionStart フックが1件加わる（既存の Stop フックはそのまま）
- 文脈には「依頼に関係するときに使う。最初の返答で全部を繰り返さない」と添え、依頼の妨げにならないようにする
- 判別のしきい値は実際の運用で見直す（SPEC M7）
