daily-log-kit v1.3.0

日報キット 操作マニュアル

Claude Code・claude.ai・Git での作業と決定を、各リポジトリの docs/log/ に日ごとに残し、作業の傾向と改善点を確かめるための道具一式です。人が書くのは短い「日報メモ」だけで、日報そのものは自動で作られます。

まず覚えること：実行する場所は4つ

このマニュアルの手順には、どこで行うかを示す札が付いています。札と違う場所で実行すると、スクリプトはその旨を表示して止まります。

札場所そこでやること
キットのフォルダC:\AllGitRepository\daily-log-kit新しい版の反映（publish-kit.bat）、各リポジトリへの配布（install-all.ps1）、複数リポジトリの分析
各リポジトリC:\AllGitRepository\<リポジトリ>git pull、日報の手動生成、そのリポジトリの分析
GitHubgithub.com（ブラウザ）PR の確認とマージ、Actions の結果の確認
Web版 / claude.aiClaude Code Web、claude.ai のチャット作業、日報メモ、「作業を分析して」の依頼、チャットの決定のメモ化
やらないことダウンロードフォルダや各リポジトリの中で publish-kit.bat や install-all.ps1 を実行しない。どちらもキットのフォルダで実行します。

全体像

キットのリポジトリは「配布元」です。導入すると各リポジトリにファイルがコピーされ、その後はキットなしで動きます。キットを使うのは導入と更新のときだけです。

日報ができるタイミング

作業中は何もしなくてよく、引き継ぎと記録は作業の区切りごとに自動で進みます。

記録されないもの: Web版 Claude Code の会話そのもの（メモの要約だけが残る）、claude.ai で頼み忘れた日の決定、コミットしない作業の時間。

日報でわかること

情報細かさ確かさ補足
コミットの日時・件名・変更行数分単位、1件ごと高Git の記録そのもの
PR の番号・題名・マージ日時1本ごと高スカッシュマージは題名の「(#番号)」から
作業日・曜日・時間帯日・3時間ごと高コミットの日時から
日報メモの記録率日ごと高導入日以降、コミットのあった日にメモがあるか
決めたこと・次にやること・判断待ちメモ1件ごと中メモの書き方しだい
PR の最初のコミットからマージまで1本ごと中マージコミットのある PR だけ
作業のまとまりと推定時間回ごと低〜中コミットの間隔が2時間以内なら同じ作業とみなす推定
判断待ちが解決したか「決めたこと」の 解決: <項目>中書けば一覧から外れる。書かなくても、新しいメモに書かれなくなれば期間を過ぎて消える

導入（初回）

キットを GitHub に置いてから、各リポジトリに配ります。キットを置く作業（手順1）が済んでいれば、手順2から始めます。

  1. キットを GitHub に置く キットのフォルダ

    zip を C:\AllGitRepository に展開し、公開リポジトリとして push します（Web版 Claude Code から設定なしで読めるように公開にします）。

    Expand-Archive daily-log-kit-v1.3.0.zip -DestinationPath C:\AllGitRepository
cd C:\AllGitRepository\daily-log-kit
node --test
git init -b main
git add -A
git commit -m "daily-log-kit v1.3.0"
gh repo create Hamm-Coder/daily-log-kit --public --source . --push
  2. スクリプトの警告を外す（初回だけ） キットのフォルダ
    Unblock-File .\install-all.ps1, .\publish-kit.ps1, .\publish-kit.bat
  3. 各リポジトリへの変更を確認する キットのフォルダ

    何も変えずに、リポジトリごとの変更予定を表示します。最後の表に「スキップ」があれば理由を確認します。

    .\install-all.ps1 -Backfill
  4. 1つだけ本番で入れる キットのフォルダ

    最初は1つで試します。PR が作られるだけで、マージするまで main は変わりません。

    Files changed で docs/log/README.md（日別の一覧）を見ます。マージ後、Actions タブの daily-log が緑になれば導入完了です。

  6. 手元に取り込む 各リポジトリ
    cd C:\AllGitRepository\RPGMZ_prototype
git pull
  7. 残りのリポジトリにも入れる キットのフォルダ

    導入済みのリポジトリは「導入済み（変更なし）」になるだけなので、全体に対して実行して構いません。

    .\install-all.ps1 -Backfill -Apply -CreatePR
過去のチャットの決定も入れたいときそのリポジトリに対応する claude.ai のプロジェクトで prompts/3-claude-ai-chat-backfill.md を使い、出てきた zip を Web版に「日報メモとして追加して PR にして」と渡します。

毎日の使い方

Web版 / PC

Claude Code で作業する日

始めは「前回の続きをして」で通じます（引き継ぎが自動で渡されます）。最後に「日報を書いて」。頼み忘れても Stop フックが1回促します。メモは作業と同じ PR に入ります。

claude.ai

チャットで決めた日

チャットの最後に依頼文4（prompts/4-claude-ai-daily-wrapup.md）を貼り、出てきたメモを Web版に「日報メモとして追加して」と渡します。

各リポジトリ

PC で作業を始めるとき

最初に git pull。ボットの日報コミットを取り込み、衝突を防ぎます。複数のリポジトリをまとめて取り込むなら、キットのフォルダ で .\pull-all.ps1（日報の仕組みを入れたリポジトリだけが対象。一覧から「全部」「番号で選ぶ」「やめる」を選びます。確認なしで全部なら -Yes）。Unity などのエディタは pull の後で開きます。

キットのフォルダ

全部のリポジトリを見渡すとき

セッション開始時の引き継ぎ

Claude Code のセッションを始めると、日報から次の4つが自動で Claude に渡されます。あなたが読む必要はなく、「前回の続きをして」「D4 をやって」と頼むだけで、Claude が準備から始めます。

次にやること

最新の日報メモから。作業キューの番号（例 D4）があれば、SPEC.md の完了条件と実行場所を添えます。Web版では PC の作業に「この環境ではできない」と付きます。

判断待ち

直近のメモの「未解決・判断待ち」。最初に出た日と回数つき。決めたら「決めたこと」に 解決: <項目> → <決めた内容> と書くと外れます。

前回詰まったこと

最新のメモの任意の見出し「詰まったこと」。分析では同じことで何度も詰まっていないかと、任意の「手応え（1〜5）」の平均を見ます（評価には使いません）。

始める前の準備

git pull が要るか、未コミットの変更、node_modules がない、Git LFS がない、作業中のブランチ。次の作業に合わせた準備のルール。

効率化の候補

同じ準備作業や似た作業の繰り返し、何度も繰り越されている作業、修正が続いているファイル。

効率化の候補が出たら

候補見つけ方次にやること
準備作業の繰り返し「登録」「起動」「取り込み」「同期」「ビルド」などが3日以上のメモに出る（対象が違っても数える）手順をスクリプト（例 tools/setup.ps1）か Skill に。毎回必要なら上の準備のルールへ
似た作業の繰り返し似た作業が3日以上に出る（ひらがなの違いや番号の違いは無視）Skill（.claude/skills/）か npm スクリプトにまとめる
繰り越し同じ「次にやること」が3回以上のメモに3日以上残る着手できない理由（PC が要る、判断待ち、準備不足）を確かめ、分割するか作業キューに戻す
修正の集中同じファイルの修正コミットが30日で3回以上そのファイルのテストか検査を作業キューに追加する

止めたいときは環境変数 DAILY_LOG_SKIP=1。ネットワークを使わないので、git pull が要るかは「最後に取得した時点」で判断します。

新しい版の反映

キットを改良したときの流れは2通りです。今後は A（Claude Code で直接直す）を基本にします。

A. Claude Code で直接直す

  1. 直したい内容を頼む Web版

    キットのリポジトリのセッションで、内容と「版を上げて PR にして」と頼みます（手順は CLAUDE.md、貼り付ける依頼文は prompts/5-claude-code-kit-improve.md にあります）。

  2. PR をマージする GitHub

    Actions の kit-ci が緑であることを確認してからマージします。kit-release がタグとリリースを作ります。

  3. 各リポジトリに配る キットのフォルダ
    cd C:\AllGitRepository\daily-log-kit
git pull
.\install-all.ps1
.\install-all.ps1 -Apply -CreatePR

B. zip を使う（publish-kit）

  1. zip をキットのフォルダに置く キットのフォルダ

    ダウンロードフォルダに置いたままでも見つけます（キットのフォルダが優先）。複数あれば版番号の一番大きいものを使います。置いた zip はコミットされません。

  2. publish-kit.bat をダブルクリック キットのフォルダ

    zip を publish-kit.bat にドラッグ＆ドロップしても同じです。

  3. 変更一覧を見て y を押す

    テストが失敗した場合や y 以外を押した場合は、上書き前の状態に戻って止まります。

  4. 各リポジトリに配る キットのフォルダ

    画面の最後に表示されるコマンド（.\install-all.ps1 -Apply -CreatePR）を実行します。

publish-kit が自動で行うこと止まる条件
1. 事前確認と GitHub との同期main 以外のブランチ、未コミットの変更がある
2. zip の展開と版の確認今より新しくない版、公開済みの版
3. キットのフォルダへ上書きコピーの失敗
4. テスト（キットの決まりの検査を含む）1件でも失敗（元に戻す）
5. 変更一覧の表示と確認y 以外（元に戻す）
6. コミット・タグ・pushpush の失敗（表示された1行を実行）
7. 一時フォルダの削除と次の手順の表示—
v1.1.x から v1.2.0 以降へ反映するときv1.2.0 では RPGMZ_Prototype 専用の extras/ を削除しました。publish-kit は zip にないファイルを消さないので、反映の後にキットのフォルダで git rm -r extras → git commit -m "extras を削除" → git push を実行します。

改善点の判定（13種類）

改善点出る条件（既定）次にやること
日報メモの書き忘れ導入後、コミットのあった日のメモが80%未満Stop フックの設定を確認、PC作業の日は「日報を書いて」
深夜のコミットが多い0〜4時が25%以上深夜の PR は翌朝見直してからマージ
PR がマージまで長い中央値3日超PR を作業キュー1項目に絞る
放置されたブランチ未マージで14日以上更新なし削除するか PR にする
大きなコミット（情報）1000行または50ファイル以上素材の取り込みなら不要。コードなら分ける
修正の割合が高い直近14日で30%以上テストや検査を作業キューに追加
判断待ちの繰り越し2回以上のメモに出て7日以上次のチャットで決めるか期限を決める
PC作業がたまっている「（PC）」が5件以上PC作業の日を決める
作業がない（情報）14日以上再開時は最新メモの「次にやること」から
準備作業の繰り返し（提案）同じ種類の準備作業が3日以上スクリプトか Skill にまとめる
似た作業の繰り返し（提案）似た作業が3日以上Skill か npm スクリプトにまとめる
繰り越し同じ「次にやること」が3回以上のメモに残る着手できない理由を確かめる

困ったとき

GitHub で既定のブランチを変えた（例: claude/... から main へ）

GitHub 側は何もしなくて大丈夫です。日報の自動更新（daily-log Actions）は実行のたびに既定のブランチを確かめるので、変えた後は新しい既定のブランチへの push で動きます。

PC のリポジトリは、clone したときの既定のブランチを覚えたままで、git pull では変わりません。キットのフォルダ の .\install-all.ps1 と .\pull-all.ps1 が実行のたびに GitHub に確かめ直すので（v1.9.1）、更新の PR は新しい既定のブランチ向けに作られます。変わっていたら「既定のブランチが … から main に変わっていました」と表示します。

pull-all.ps1 はブランチを切り替えません。各リポジトリ の作業フォルダを新しい既定のブランチに移すのは、手で行います。

git switch main
git pull
git pull で「untracked working tree files would be overwritten」

手元の未追跡のファイル（Unity の ProjectSettings/ProjectVersion.txt など）と、GitHub 側で追加されたファイルがぶつかっています。キットのフォルダ の .\pull-all.ps1 なら、同じ内容は置き換え、違う内容は .local に退避して自動で取り込みます（v1.5.1 から）。手で行うときは、エディタを閉じ、手元のファイルを別名に退避してから pull します。各リポジトリ

git log --oneline HEAD..origin/main -- ProjectSettings/ProjectVersion.txt
Move-Item ProjectSettings\ProjectVersion.txt ProjectSettings\ProjectVersion.txt.local
git pull
fc.exe ProjectSettings\ProjectVersion.txt ProjectSettings\ProjectVersion.txt.local

中身が同じなら .local を消します。違うなら、どちらの Unity の版で続けるかを決めます。git stash -u や git clean は使いません（Library フォルダなどを巻き込むことがあります）。

install-all.ps1 で「スキップ: リモートに chore/daily-log-v… が既にあります」

同じ版の導入 PR が未マージのまま残っています。GitHub でその PR をマージするか閉じてから、もう一度実行します。手元のブランチが原因のときは git branch -D chore/daily-log-v<版> を実行します。

install-all.ps1 で「キットが GitHub より N コミット古いです」

古い版を配らないための安全装置です。キットのフォルダ で git pull してから実行し直します。

表示対処

robocopy は成功しても 0〜7 を返します（1＝コピーあり）。最後の表の「失敗」の列が 0 なら問題ありません。8 以上が失敗です。

Actions の daily-log が失敗する

Actions タブで失敗した実行を開き、赤いステップのログを見ます。「push に失敗」なら main のブランチ保護が原因なので、そのリポジトリはワークフローを削除し、PR の中で node tools/daily-log.mjs generate する運用にします（仕様書9章）。

.ps1 を実行すると「デジタル署名されていません」

ダウンロードしたファイルに付く印が原因です。Unblock-File .\install-all.ps1 を実行するか、ファイルのプロパティで「許可する」にチェックします。publish-kit.bat は中で実行ポリシーを指定しているので、そのまま動きます。

日報に深夜の作業が前日として出る

仕様です。作業日の区切りは朝4時です。カレンダーどおりにしたい場合は docs/log/config.json の "dayStartHour" を 0 にします。
