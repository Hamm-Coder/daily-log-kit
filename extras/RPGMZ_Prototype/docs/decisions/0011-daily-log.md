# ADR 0011: 日報の仕組み（daily-log-kit）を導入する

- 状態: 採用
- 日付: 2026-11-13
- 関連: `docs/specs/daily-log.md`、`docs/procedures/daily-log.md`、ADR 0003（Web版を主軸）、ADR 0005（main のブランチ保護なし）

## 背景

2026-11-10 に活動ログ（10/31〜11/10）を作ったところ、11/03〜11/07 はコミットがなく、作業内容（世界設定づくり）は claude.ai の過去チャットを検索して復元するしかなかった。チャットには発言ごとの日時がないため、日付の一部は推定になった。Web 版 Claude Code の会話もリポジトリには残らない。

決めたことと作ったものを、作業の当日にリポジトリへ残す仕組みが必要。同じ問題は他のリポジトリにもあるため、どこにでも入れられる形にしたい。

## 選択肢

| 案 | 内容 | 費用 | 作業時間 | 保守性 | U2U移行への影響 |
| --- | --- | --- | --- | --- | --- |
| A 手書きの日報 | 毎日 `docs/log/日付.md` を書く | 0円 | 毎日5〜10分 | 書き忘れる。並行PRで衝突する | なし |
| **B daily-log-kit** | セッションごとのメモ＋Git履歴から自動生成。Stop フックで書き忘れを防ぎ、Actions で日報を作り直す | 0円（Actions は公開リポジトリ無料、非公開は無料枠内の見込み。1回1分未満） | 導入数分、以後はほぼ0 | キットを別リポジトリで版管理し、一括で配れる | なし（Git とテキストのみ） |
| C 外部サービス（Notion 等） | チャットとコミットを外部に集約 | 無料〜有料 | 連携設定が必要 | リポジトリと二重管理になる | なし |

## 決定

案Bを採用する。

- 日報メモは `docs/log/entries/<日付>/` にセッションごとに書く（並行PRで衝突しない）
- 日報 `docs/log/YYYY-MM/YYYY-MM-DD.md` と一覧は自動生成し、手で編集しない
- 作業日は日本時間の4時区切り（深夜作業を前日に含める）
- main への push で GitHub Actions が日報を作り直す（ADR 0005 によりボットが push できる）
- 過去の分は `generate --all` と、活動ログ（`claude/ACTIVITY-LOG-2026-11.md`）から起こしたチャット分のメモで補う

## 影響

- `CLAUDE.md` に日報の区間が加わり、Claude Code はPRを作る前に日報メモを書く
- Stop フックが1本増える。差分があってメモがないときに1回だけ促す（作業は止めない）
- main にボットのコミット「docs(log): 日報を更新」が入る。PC では作業前に `git pull` が必要
- 同じキットを他のリポジトリにも `install-all.ps1` で入れる

## 見直す条件

- main にブランチ保護を入れる場合（Actions を外し、PR内での生成だけにする）
- 日報メモの書き忘れが続く、または記録の手間が作業時間を圧迫する場合
